# BRIEF — mercurius-browser

Браузер агента Меркурий: Chromium из Debian под puppeteer-core за небольшим API на Fastify. Агент открывает страницы,
читает их текст, нажимает, вводит, выбирает в списках, делает снимки экрана и запускает свои скрипты. Без модуля агент
работает, но без инструмента `browser`.

## Назначение и границы

Сервис делает:

- держит один Chromium на профиль и одну текущую страницу в нём; входы профиля лежат на диске и переживают перезапуск;
- отдаёт страницу снимком: адрес, заголовок, текст, пронумерованные элементы, закрытые окна страницы;
- выполняет действия над элементом по номеру из снимка;
- проверяет каждый запрос страницы на внутренние адреса и пускает соединения только через свой прокси.

Остаётся в приложении (`src/App/Agent/Tool/Web/BrowserTool.php`, `src/Infrastructure/Browser/BrowserClient.php`):

- какой профиль у участника и проекта — путь вычисляет агент, модель называет только имя;
- подтверждения: карточки владельца для нажатий и отправки форм (`BROWSER_CONFIRM`), для внутреннего адреса и для
  скрипта на живой странице;
- чтение файла скрипта из песочницы участника, хеш и разрешение на пару «сайт + хеш»;
- маскировка секретов в результате, рамка недоверенных данных, отправка снимка в чат и модели зрения.

## Устройство

| Путь / файл | Что делает |
|---|---|
| `GET /health` | `{"ok": true, "sessions": N}`, без токена |
| `POST /navigate` | открывает `url`; `allow` — до 4 хостов, разрешённых владельцем для этой страницы; ответ — снимок |
| `POST /read` | снимок текущей страницы профиля |
| `POST /click` | нажатие на элемент `ref`; вкладка, открытая нажатием, становится текущей |
| `POST /type` | ввод `text` только в поле ввода; Enter — только при `submit: true` |
| `POST /select` | вариант списка по значению, тексту или однозначной части текста |
| `POST /scroll` | `down`, `up`, `top`, `bottom` |
| `POST /back` | назад по истории; на первой странице — `409` |
| `POST /evaluate` | скрипт `source` с `args`: `mode: read` — на замороженной копии, `act` — на живой странице; `host` должен совпасть с открытой страницей |
| `POST /screenshot` | PNG страницы в base64 |
| `POST /close` | закрывает браузер профиля |
| `POST /adopt` | переносит профили старой плоской раскладки в каталог владельца `p<номер>` |
| `src/server.ts` | API, сессии профилей, снимок страницы, замороженная копия для скриптов чтения |
| `src/guard.ts` | проверка адресов (IPv4, IPv6, IPv4 внутри IPv6), правило профиля, проверки скрипта чтения, выбор варианта списка |
| `src/proxy.ts` | HTTP-прокси на loopback: резолвит имя один раз и соединяется с проверенным адресом |

Профиль — `p<участник>/<имя>` или `p<участник>/projects/<проект>/<имя>`, имя — `[a-z0-9][a-z0-9_-]{0,31}`; другой вид
профиля — `400`.

## Безопасность и пределы

- Вход — `Authorization: Bearer <BROWSER_TOKEN>`, сравнение за постоянное время; токен короче 16 символов — сервис
  не стартует.
- Каждый запрос страницы (документ, скрипты, картинки, перенаправления) проходит `refusal`: только `http(s)`, имя без
  точки — отказ, все адреса имени должны быть публичными. Хосты из `allow` пропускаются.
- Chromium ходит только через прокси профиля (`--proxy-server`, `--proxy-bypass-list=<-loopback>`): между проверкой и
  соединением нет второго ответа DNS.
- Вкладки, открытые страницей, получают ту же проверку запросов.
- Скрипт чтения: копия текущего DOM без собственных скриптов страницы, пока копия грузится — только GET и HEAD к тому
  же хосту, перед скриптом вкладка уходит в offline. Копия закрывается после скрипта.
- Окна `alert`, `confirm`, `prompt`, `beforeunload` закрываются сразу; хранится до 20 последних.
- Пределы в коде: тело запроса — 1 МБ; переход — 30 с; ожидание тишины сети — до 8 с; текст снимка — 60 000 символов;
  элементов — 200; вариантов списка в снимке — 30; скрипт — до 200 000 символов и 30 с; результат — 60 000 символов;
  один скрипт на профиль одновременно; соединение прокси — 15 с; сессия закрывается после 10 минут без запросов.
- Образ: пользователь `browser` (uid 10010), `dumb-init`. Compose: своя сеть `browser` (только приложение и
  браузер — без базы и песочницы), `mem_limit: 1536m`, `shm_size: 512m`, `no-new-privileges`, профили — в
  `storage/browser`.

## Решения

- Сеть страницы — только через прокси на проверенный адрес: защита от подмены DNS между проверкой и соединением.
- Окна страницы закрываются сразу, текст — в следующем ответе: открытое окно держало бы страницу.
- Вкладка, открытая страницей, становится текущей: агент работает с одной страницей.
- `type` не нажимает Enter на переводе строки, не щёлкает мышью: отправка только явным `submit` или `click`.
- Произвольного кода модели нет: только скрипты-файлы из песочницы, переданные приложением в `/evaluate`.
- Скрипт чтения работает на копии в offline: не может ничего отправить даже со злым умыслом. Блок-листы CDP
  WebSocket в Chromium не останавливают, offline останавливает.
- Профили разложены по участникам и проектам: чужой профиль модели недоступен.
- Chromium — из пакетов Debian, библиотека — puppeteer-core, которая своего браузера не скачивает; путь — `CHROMIUM_PATH`.
- Сборка TypeScript — на отдельной стадии образа: зависимости разработки в итоговый образ не попадают.

## Проверки

- `npm run check` — проверка типов `tsc --noEmit`, ESLint и тесты `node --test` (`test/actions.test.ts`,
  `test/guard.test.ts`, `test/proxy.test.ts`). Тестам не нужны ни браузер, ни сеть.
- CI (`.github/workflows/ci.yml`): одна задача, Node 22, `npm ci` и `npm run check`; изменения только в `*.md` CI не
  запускают.

## Связь с Меркурием

- Профиль compose — `browser`: добавить в `COMPOSE_PROFILES`.
- `.env`: `BROWSER_TOKEN` (пусто — браузера у агента нет), `BROWSER_URL` (`http://browser:3000`), `BROWSER_CONFIRM`
  (`1` — нажатия и отправка форм через карточку владельца).
- Инструмент `browser` предлагается модели, только пока сервис отвечает на `/health`. При старте агент один раз
  вызывает `/adopt` с каталогом владельца.
