# mercurius-browser

Браузер агента [Меркурий](https://github.com/opencck/mercurius): Chromium из Debian под puppeteer-core за небольшим API
на Fastify. Модуль Меркурия, работает и сам по себе. Без него агент тоже работает — просто без инструмента `browser`.

## API

Все пути, кроме `/health`, требуют `Authorization: Bearer <BROWSER_TOKEN>`. Тело — JSON; `profile` (по умолчанию
`main`) — профиль, входы в котором переживают перезапуск (`[a-z0-9][a-z0-9_-]{0,31}`).

| Путь | Что делает |
|---|---|
| `GET /health` | `{"ok": true, "sessions": N}` |
| `POST /navigate` | открывает адрес |
| `POST /read` | текст страницы, её ссылки и поля |
| `POST /click`, `POST /type` | действие с элементом; `type` пишет только в поле ввода, перевод строки вводится как текст, отправляет только `submit` |
| `POST /select` | выбирает вариант списка по значению, тексту или части текста, которая есть только у одного варианта |
| `POST /scroll` | прокручивает `down`, `up`, к началу (`top`) или к концу (`bottom`) |
| `POST /back` | назад по истории страницы |
| `POST /evaluate` | скрипт: на замороженной копии без сети — чтобы читать, или на живой странице — чтобы действовать |
| `POST /screenshot` | PNG страницы |
| `POST /close` | закрывает страницу профиля |
| `POST /adopt` | переносит профили старой плоской раскладки в набор владельца (`{"owner":"p1"}`), входы сохраняются |

Окно страницы (`alert`, `confirm`, `prompt`, `beforeunload`) закрывается сразу, его текст приходит со следующим ответом (`dialogs`): открытое окно держало бы страницу. Вкладка, которую открыла страница, становится текущей.

Каждый запрос страницы сверяется со списком внутренних и частных адресов (`src/guard.ts`) и уходит через прокси на
loopback, который соединяется с проверенным адресом (`src/proxy.ts`): страница не достаёт до сети хоста. Сессия закрывается после 10 минут без запросов.

## Настройки

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `BROWSER_TOKEN` | — | обязательна, от 16 символов |
| `PORT` | `3000` | порт |
| `PROFILES_DIR` | `/profiles` | где лежат профили со входами: `p<участник>/<имя>`, `p<участник>/projects/<проект>/<имя>` |
| `CHROMIUM_PATH` | `/usr/bin/chromium` | браузер |

## Запуск

```sh
docker build -t mercurius-browser .
docker run --rm --shm-size=512m -e BROWSER_TOKEN=$(openssl rand -hex 32) -p 3000:3000 mercurius-browser
```

В Меркурии сервис — в профиле compose `browser`: добавьте его в `COMPOSE_PROFILES` и задайте `BROWSER_TOKEN` в `.env`.

## Разработка

Сервис написан на TypeScript (Node.js 22): исходники — в `src/` (`server.ts` — API, `guard.ts` — проверка адресов и
вспомогательные функции, `proxy.ts` — прокси на loopback), тесты — в `test/`. `tsc` собирает и то и другое в `dist/`;
образ Docker собирает их на отдельной стадии и запускает `dist/src/server.js`.

```sh
npm install
npm run build    # сборка в dist/
npm start        # запуск dist/src/server.js
npm run check    # проверка типов TypeScript, ESLint и тесты
```

Тестам не нужны ни браузер, ни сеть (тесты прокси открывают сокеты на loopback). CI запускает `npm ci` и
`npm run check`.
